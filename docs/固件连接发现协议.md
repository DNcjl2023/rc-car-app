# 固件·车辆连接与发现协议（v0.12.1）

> 本文件是「固件侧」与「App 侧（Mac 上修改的 rc-car-app）」之间的连接/发现协议约定。
> 固件版本：`v0.12.1`（方案 C：短时 AP 配网 + STA 联网后立即关闭 AP + UDP 设备发现）
> 芯片：ESP32-CAM（AI-Thinker，OV2640），电机：L298N（GPIO 12/13/14/15）
> 工程：`firmware/`（PlatformIO，upload_port = COM4）

---

## 1. 端口一览

| 用途 | 协议 | 端口 | 说明 |
|------|------|------|------|
| 遥控控制 | TCP | 3333 | 二进制帧（见 §3） |
| 视频流 | TCP (MJPEG) | 81 | `GET /stream` |
| **设备发现** | **UDP 广播** | **8889** | `RC-DISCOVER`（见 §4） |
| 调试日志 | UDP | 8888 | 仅开发期电脑监听 |

## 2. 设备标识与热点

- **设备唯一 ID（deviceId）**：12 位**大写**十六进制字符串，由芯片 eFuse MAC 低 48 位生成。
  - 生成方式（固件内）：`MAC = ESP.getEfuseMac() & 0xFFFFFFFFFFFFULL`，格式 `%012llX`。
  - 例：`8CAAB5ABCDEF`。App 用它命名车辆、持久化到列表。
- **AP 热点 SSID**：`RC-CAR-XXXX`，其中 `XXXX` 为 MAC 末 4 位十六进制。
  - 例：`RC-CAR-29E0`（由芯片自动生成，不再写死）。
  - **AP 密码**：`12345678`。
  - **AP 网关 IP**：`192.168.4.1`（默认，App 连热点时可先连此 IP 发送配网）。

### 2.1 AP 工作策略（方案 C）

固件不会让 AP 在已配网车辆上永久常驻，以减少 Wi-Fi 对视频流和控制链路的带宽影响。AP 分为三种状态：

| 状态 | 触发条件 | AP 行为 | 说明 |
|------|----------|---------|------|
| AP_HOLD | 未保存配置，或 AP 窗口结束时 STA 仍未连接 | AP 常开 | 未配网时等待 App 发送 0x04；已配网但未连上 STA 时继续后台重连 |
| AP_WINDOW | 已保存配置，车辆上电或 STA 长时间掉线 | 最多开放 60 秒 | 车辆后台连接 STA；STA 未连上前保留 AP 供重新配网 |
| AP_OFF | STA 已连接时立即进入 | AP 关闭 | 车辆只以 STA 在线，App 通过局域网 UDP 发现来获取最新 IP |

补充规则：

- 已配网车辆上电后 AP 最多开放 **60 秒**；STA 一旦连接成功会立即关闭 AP，不再等待窗口结束。
- 60 秒窗口仅用于等待 STA：若超时仍未连接，AP 保持开放，避免车辆失联。
- AP 关闭后若 STA 掉线超过 **30 秒**，车辆会重新开放 AP 窗口；STA 未恢复时窗口结束后保持 AP，避免车辆彻底失联。
- AP 开启期间，设备发现广播使用 192.168.4.1；App 只应把它用于配网/连接热点阶段，不应把它当作车辆长期在线时的控制地址。
- 清网命令 0x03 d0=6 会删除保存的 Wi-Fi 凭据并重启车辆。重启后因为无配置，车辆会回到 AP_HOLD 纯 AP 状态，便于转手或清除隐私信息。

## 3. 遥控控制帧（沿用既有协议，未改动）

### 3.1 帧格式（7 字节定长）
```
[0]=0xAA  [1]=0x55  [2]=type  [3]=d0  [4]=d1  [5]=d2  [6]=crc8(前6字节, poly=0x07)
```

### 3.2 类型
| type | 含义 | 参数 |
|------|------|------|
| `0x01` | 摇杆控制 | d0=steering(0..255, 127=中), d1=throttle(0..255, 127=中) |
| `0x02` | 参数配置 | d0=1 → d1/100=速度上限(0..100) |
| `0x03` | 命令 | d0=1 STOP(急停), d0=2 resume, d0=6 清除已保存 WiFi 并重启 |
| `0x04` | 配网 | 变长帧，见 §3.3 |

### 3.3 配网帧 `0x04`（用于 AP 模式发送 WiFi 信息）
```
[0]=0xAA  [1]=0x55  [2]=0x04  [3]=ssidLen  [ssid...]  [passLen]  [pass...]  [crc8(全部前序字节)]
```
- ssidLen ≤ 32，passLen ≤ 64。
- App 连上车辆热点后，通过 TCP「AP IP:3333」发送此帧；车辆保存 WiFi → 重启 → 以 STA 联网。

## 4. 设备发现广播（新增，本版本核心）

### 4.1 帧格式（UDP 明文文本，无换行、无头）
```
RC-DISCOVER <deviceId> <ip>
```
- 例：`RC-DISCOVER 8CAAB5ABCDEF 192.168.0.108`
- 分隔：单个空格；`deviceId` 为大写 hex；`ip` 为当前 STA IP（AP 模式下为 AP 网关 IP）。

### 4.2 发送方（固件）
- **广播目标**：
  - STA 已联网：子网定向广播 `localIP() | ~subnetMask()`（如 `192.168.0.255`）。
  - AP 模式：`255.255.255.255`。
- **发送时机**：
  1. STA 联网成功时**立即**广播一次。
  2. 之后每 **10 秒**持续广播一次（`controlTask` 内）。
- 发送端口：UDP **8889**。

### 4.3 接收方（App）
- 监听 UDP **8889** 端口。
- 按空格拆分获得 `deviceId` 与 `ip`，以 `deviceId` 作车辆唯一命名，更新该车最新 IP。
- 多车共存：以 `deviceId` 区分，互不冲突。
- 断线/重连后 IP 变化，靠 10s 广播自动刷新。

> ⚠️ 注意：若 App 所在网络与车辆不在同一子网（例如车辆在 2.4G，手机在 5G），UDP 广播可能到不了。联调时请确认手机与车辆连同一路由器/同一网段。

## 5. App 对接要点（Mac 侧）

1. **首次配网**：无配置车辆会常开 `RC-CAR-XXXX` 热点。App 引导用户连接该热点 → 在 `192.168.4.1:3333` 发送 `0x04` 配网帧 → 车辆保存并重启 → 提示用户切回家里 WiFi。
2. **持续发现**：车辆 STA 联网后，App 在局域网（家里 WiFi）监听 UDP 8889，拿到 `RC-DISCOVER <deviceId> <ip>` 后把车辆加入/更新列表。若收到 `192.168.4.1`，表示车辆处于 AP 配网窗口，不应把它当作 STA 控制地址。
3. **再次连接**：App 保存 deviceId → ip，点选车辆即直接用最新 ip:3333 连接控制、ip:81 拉视频流。车辆重启后 IP 可能变化，应以 UDP 发现帧为准。
4. **重新配网**：最可靠方式是在 STA 在线时先发送清网命令 `0x03 d0=6`，车辆重启为纯 AP 后再发送 `0x04`。直接重启已配网车辆时，原 Wi-Fi 一旦连接成功，AP 会立即关闭。
5. **权限**（iOS）：
   - `NSLocalNetworkUsageDescription`（本地网络权限），否则收不到局域网 UDP 广播。
   - 前台运行时监听广播即可；如需后台常驻发现，用后台任务（受系统限制）。
6. **权限**（Android）：`INTERNET`、`ACCESS_WIFI_STATE`、`CHANGE_WIFI_STATE`（配网切热点用）。

## 6. 联调工具

- 电脑监听发现广播：`python firmware/scripts/udp_listen.py`（默认 8888；改端口 8889 即可看 `RC-DISCOVER`）。
- 电脑端配网：`python firmware/scripts/provision.py "SSID" "密码"`（连热点后运行）。
- 串口日志：`pio device monitor`（波特率 115200），会打印 `[id]`、`[wifi]`、`[disc]`。
